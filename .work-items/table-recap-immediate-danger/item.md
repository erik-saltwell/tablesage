# Table Recap: reserve the immediate danger for genuine urgent threats

Any immediate-danger content in the Table Recap should name only a real, urgent threat at the moment play resumes, and be left out when there is none. The recap should end on the actual cliffhanger. In Session 004 that's the partly broken-through cave-in at the mine entrance, not Dunk's possibly cursed ring, which is a mystery or hook.

The old Table Recap has no immediate-danger section; it ends with "Next". The user put this on both artifacts for now. If the replacement recap renders `present_matters.present_danger` (see [004 present_matters.json](../../deployment/campaigns/Brandonsford/004/present_matters.json) and the [Post-Session Matters specification](../post-session-matters/specification.md)), an upstream fix in the Present Matters danger definition covers both.
