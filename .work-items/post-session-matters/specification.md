# Post-Session Matters Contract

> **Table Recap amendment (2026-10-28):** The [Spoken Table Recap contract](../table-recap-read-aloud-split/specification.md) enables a separate LLM presentation step from the current Session Summary. It supersedes statements below that Table Recap is paused or consumes other source artifacts. The deterministic Summary and campaign preparation behavior are unchanged.

`post_session_matters.json` is a visible TableSage artifact labeled **Post-Session Matters**. Deterministic code assembles it from this Session's ten filtered Matters publications. It makes no LLM call, reapplies no filters and changes no source fields, IDs, ordering or data. Scene Log remains a separate artifact. The individual Matters remain hidden and continue to be the state consumed by extractors and subsequent Sessions.

The exact top-level fields are `version: 1`, `session_id` (the owning Session UUID), `historical_matters`, `present_matters`, and `open_matters`. Historical Matters contains Developments, Revelations and New Assets from the Session just completed, not the preceding Session. Present Matters copies the existing `current_position` string and `present_danger` array. Open Matters contains Goals, Goal Impediments, Opportunities, Mysteries, Obligations and Brewing Troubles under their existing snake_case keys. Every category is required even when its array is empty. This preserves the current stopping situation without confusing it with Ledger's bootstrap starting situation. Immediate goals are excluded by the source Present Matters schema and therefore by the combined schema.

All ten source artifacts must be current and validate against their existing schemas. The combined document has a strict envelope/group schema and uses the current category schemas for its nested content. No partial result or replacement of missing inputs with empty arrays is allowed. Assembly must preserve the previous combined file and completion record if validation or writing fails. Successful atomic persistence records fingerprints captured before assembly; concurrent input changes leave the result stale.

The producer depends on the ten current-Session artifact references, the combined schema and the owning Session UUID. Category schema changes already propagate through their source artifacts. It has no direct prior-Session, Scene Log, roster, Glossary or model-setting dependency. Those requirements remain transitive through the source producers. Changing a source artifact or the combined schema makes the combined artifact stale; regeneration repairs only required missing/stale prerequisites. Regenerating the combined output alone must not call an LLM, require an API key or allocate new IDs.

The existing Generate Artifacts processing row includes the new artifact in its completion requirements. Session Detail, Regenerate Artifact, Export Artifact and Clean Session use the existing registry-driven behavior; the new export is JSON only, with no new viewer or Markdown companion. The subsequent [Deterministic Session Summary contract](../deterministic-table-recap/specification.md) renders this artifact as Markdown. Table Recap and campaign preparation generation remain disabled.

Python implementation files are not fingerprinted. Code changes require explicit regeneration when their effects should be applied; old recorded Python inputs are ignored without migration.
