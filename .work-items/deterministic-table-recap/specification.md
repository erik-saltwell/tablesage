# Deterministic Session Summary Contract

> **Table Recap amendment (2026-10-28):** The [Spoken Table Recap contract](../table-recap-read-aloud-split/specification.md) enables a separate LLM presentation step from the current Session Summary. It supersedes statements below that Table Recap is paused or consumes other source artifacts. The deterministic Summary and campaign preparation behavior are unchanged.

> **Amended 2026-10-28 by [Improve Phrasing](../summary-improve-phrasing/idea.md).** The Summary stays model-free. Headings are now defined in the template's literal `headings` mapping ("Last session...", "You learned", "You gained", "Your goals", "Standing in your way", "What could help", "Still unanswered", "Promises and debts", "Meanwhile", "As we return", "The danger right now"). Read-aloud wording (sentence case, bullets fitted to their heading; the party stays "the party") is written upstream by the Matters prompts, so the Summary's "do not infer tense or pronouns" rule still holds: it copies the Matters wording as written. A separate model phrasing pass was briefly added and then removed the same day; any leftover `summary.phrasing.json` is archived and deleted on the next Summary write.

Each Session's `summary.md` is its structured, human-readable Session Summary. It consumes that Session's current, valid `post_session_matters.json`, the existing Session cue from its current Scene Log, and recorded Campaign/Session metadata. This replaces the paused, model-generated Summary contract. Table Recap and campaign preparation generation remain paused. Use the existing artifact, regeneration action, export action and Generate Artifacts row; add no UI screen or model prompt.

Render a Markdown title and labeled bullet lists for every Matters group, with Developments under `Previously`. Include one bullet for Current Position and one per entry in all array groups, in this order: Developments (`title`), Revelations (`text`), New Assets (`name`), Goals (`title`), Goal Impediments (`title`), Opportunities (`title`), Mysteries (`title`), Obligations (`title`), Brewing Troubles (`title`), then Current Position and Present Danger. End with the stopping situation so the reader can resume play. Preserve source order within categories, normalize whitespace and sentence punctuation, and use brief fixed transitions. Skip empty categories and suppress exact repeated read-aloud text entries, preferring their final orientation placement when the same text appears earlier. Do not infer tense, pronouns, links, causes or new facts; do not truncate or apply new quality filters.

Only primary fields are read. Opportunity titles summarize the opening, action and potential advantage; do not append their separate detailed fields. Omit descriptions, details, benefits, separate opportunity openings/actions/advantages, IDs, references, lifecycle/status fields, ratings and justifications. There are no explanations of category meanings or placeholders for empty groups. The already-filtered publication determines which Matters qualify.

Presentation lives in the packaged `session_pipeline/session_summary.j2` Jinja template, editable without changing Python. It controls headings, transition wording, section order, conditional layout and paragraph/list formatting. Python validates the publication and prepares only the permitted primary text, normalizes punctuation/whitespace, escapes Markdown and removes duplicates. The preserved layout uses the Campaign name as its title, a bold date/cue line and category headings. The template receives the owning Campaign’s `campaign_name` string, `session_date` as an ISO `YYYY-MM-DD` string or `None` for an undated Session, `session_cue` as a single-line string copied from the Scene Log, `historical_matters` and `open_matters` as dictionaries of prepared text lists, and `present_matters` with a `current_position` string and a `present_danger` list. It uses StrictUndefined, reads the current file on every render and rejects an empty result before persistence.

The producer depends on Post-Session Matters, the current Scene Log, the packaged Jinja template, the Campaign name and the recorded Session date. The existing Scene Log cue is reused without model generation or reselection. Undated Sessions omit the date in the default title; empty cues and foreign-Session Scene Logs are rejected. No direct prior-Session, model, credential or length-setting dependency is introduced. Missing/stale prerequisites rebuild through the graph when generation is requested; direct rendering rejects missing/stale/malformed inputs and foreign Session UUIDs before writing. Snapshot inputs before rendering; races leave the result stale. Use existing rollback-safe persistence and interruption handling. Current output is Markdown only; any old structured Summary companion remains a legacy cleanup file, not a required output or current recap input.

Existing summaries are archived by content hash under `legacy/narrative/` before requested replacement, including any old JSON/input companions. Existing Table Recap files stay untouched and exportable. Table Recap generation is paused through both the TUI and CLI until its replacement is defined. No automatic artifact migration or generation occurs when opening a workspace.

The standalone command `tablesage regenerate-session-summary --campaign NAME --session NUMBER` resolves the Campaign by exact name and Session by sequence number in the current workspace. It invokes the direct Summary producer, never the broader generation planner, so missing/stale prerequisites cause an error rather than upstream model calls. The command requires an initialized database at the expected revision and existing valid settings, prints the output path on success, returns nonzero on failure and uses the normal generation logs/completion records. Diagnostic CLI commands retain their read-only behavior.

Python renderer and Application source files are not freshness dependencies. Template edits still invalidate Summary automatically; Python code changes require explicit regeneration when their effects should be applied. Existing Python fingerprints in older completion records are ignored without migration.
