## Prompt Checks

Scope: `prompts` (the latest pass’s prompt files). Each Summary check below has exactly the scope named by its subsection; “Across the Summary” includes comparisons with the prior Session in the same run.

#### RC-001 Prompt text never echoes the test Sessions
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a prompt's examples, rules or schema descriptions use a name, item, situation or expected answer from the test Sessions (the overtuning reference list, or this pass's own Summaries and beats). Generic vocabulary used without the Session's particulars is not a hit.
- Fix direction: replace the example with a fictional one from an unrelated setting that teaches the same distinction.
- Example: Illustration: the user rejected even a near echo: "I actually want the prompt for now to not mention people having other problems, that is too close to the session text"
- Sources: PREF-012, EX-014

#### RC-002 No rule is shaped around one Session's case
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a prompt rule exists only to fix one remembered case: its wording, even when fictionalized, singles out a particular person, object or event rather than stating a distinction that applies generally. Compare each rule with the learnings' general patterns (PREF-045 to PREF-052, listed in the learnings README); a case-shaped rule usually has one of them underneath.
- Fix direction: restate the rule as the general pattern the case exposed, or rely on an existing general rule.
- Example: Illustration: "Is there something more generic and Less situation specific that would work?"
- Sources: EX-044, EX-042 (recurrence, 2026-11-01), EX-079 (general-fix request), PREF-045 to PREF-052; APP-013 records that general rules with fictional examples replaced case-naming rules

#### RC-003 The model classifies; code decides what to show
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a prompt asks the model to decide whether something is important, interesting or worth publishing enough to keep or omit, instead of rating classification fields that code filters. This includes dropping low-rated candidates from a list, such as history candidates that touch no thread. Defining what counts as a fact kind, or excluding plain colour and routine, is not a keep/drop decision.
- Fix direction: have the model list every candidate with its rating, and move the threshold into deterministic selection, recording what it drops for review.
- Sources: PREF-014 (and its 2026-11-01 application)

#### RC-004 A prompt's own examples obey its rules
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an example in a prompt breaks a rule the same prompt states, such as attribution placed last, a hedge or reason inside a goal, or title case.
- Fix direction: rewrite the example to follow the rule it illustrates.
- Example: Illustration: a plain-language rule put the source first, while the prompt's own example still ended "…, according to Father William".
- Sources: EX-034, PREF-026

## Summary Checks

### Across the Summary

#### RC-005 The header identifies the Session
- Kind: pattern
- Direction: positive
- Status: failing
- Check: when a Session Summary is produced, it opens with the campaign name, the Session date and the Session cue.
- Fix direction: supply the missing element to the header.
- Sources: PREF-029

#### RC-006 No fact is stated twice within a tier
- Kind: pattern
- Direction: negative
- Status: failing
- Check: two bullets in the open headings, or in "Last session...", say the same thing: one bargain, promise, threat or piece of knowledge restated under another heading or split into two bullets that together add nothing. Mark each bullet of a cluster as original, restates or distinct; more than one "restates" fails. Overlap across tiers ("Last session..." versus open headings) is checked by RC-009, not here.
- Fix direction: keep one home for the fact and let other headings add only their distinct angle, such as which goal an obstacle blocks.
- Sources: PREF-004, EX-003, EX-022, EX-023, EX-024, EX-073

#### RC-007 Distinct facts about one subject all survive
- Kind: pattern
- Direction: positive
- Status: failing
- Check: when one subject carries several distinct facts (a task and its price, knowledge and the action it enables, two separate resources), each independently eligible fact survives selection and appears. Fails when deduplication merged or hid a fact that added something, judged from the run's selection and kept-and-dropped records.
- Fix direction: deduplicate only the same fact or resource, never facts that merely share a subject, thread or goal.
- Example: Illustration: the user's golden kept both "The dragon can't be killed without Sir Brandon's sword." and "If you get Sir Brandon's sword, it can help slay the dragon.": the knowledge and the action.
- Sources: EX-025, EX-026, EX-066, PREF-004, PREF-041

#### RC-008 A live threat is told once
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a danger present when play stopped appears under "Immediate danger" and again as an obstacle or threat under "Standing in your way" or "Meanwhile", with no distinct link added. "Immediate danger" may still repeat "Last session...".
- Fix direction: tell the present danger once as immediate; keep only distinct lasting facts, such as a continuing ban, in the open headings.
- Sources: EX-021, EX-067, PREF-042, PREF-017

#### RC-009 "Last session..." names the event; the open bullet carries the specifics
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a "Last session..." bullet repeats specifics, such as an amount, a condition or the remaining task, that an open bullet about the same deal states. Sharing the subject is legitimate; telling that an offer was made or a bargain struck belongs in history. the user rates this a minor issue.
- Fix direction: tell the event in history ("offered a bounty"), and leave amounts and conditions to the open bullet.
- Example: Illustration: the user's golden's "Quinn promised Sir Phidipaldi 100 gold…", beside a goal to "collect his promised 100 gold", is a small lapse the user did not flag.
- Sources: PREF-048, PREF-015, EX-057

#### RC-010 A pursuit stays open only as long as how it was established allows
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an open bullet (goal, obstacle, question, debt, threat, danger) remains although play ended it, judged by how it was established:
  - taken up or agreed, but achieved, abandoned, failed, its purpose gone, or its window passed;
  - only floated, offered or one-sided (an unaccepted challenge, a purchase being considered, an interest the characters put down), and not renewed;
  - episode-local, and the episode is over with the party gone.
  A taken-up pursuit that went unmentioned this Session is not stale. Expiry of one proposed method does not itself end a broader supported end; reconcile each separately. A missed debt deadline does not discharge what is owed, and an available offer does not expire merely because it went unmentioned; distinguish it from a floated pursuit the party never took up.
- Fix direction: carry each pursuit's lifecycle from how it was established and from evidence of its ending, including elapsed fictional time; an explicit cancellation is not required.
- Sources: EX-081, PREF-051, PREF-033, PREF-013, EX-018, EX-070, EX-072, EX-052, EX-022 (stale obligations)

#### RC-011 Sentence case
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a heading or bullet capitalizes words other than the first word and proper nouns.
- Fix direction: use sentence case throughout.
- Sources: PREF-024, PREF-002, EX-031, EX-013

#### RC-012 Each bullet reads naturally after its heading
- Kind: pattern
- Direction: negative
- Status: failing
- Check: read aloud right after its heading, a bullet repeats the heading ("Your goal is…"), continues it as one sentence, or contains field labels or mechanical suffixes.
- Fix direction: write each bullet as a complete phrase that stands on its own after the heading.
- Example: Illustration: an "impedes:" title suffix was tried and reverted.
- Sources: PREF-025, EX-039

#### RC-013 Plain, sayable wording
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a bullet drops articles, "is/are/was" or prepositions; hides who acted, believes, offers or owes behind a later clause; puts attribution last; or stacks three or more clauses in one sentence. Optional recognition cues and repeated profiles are RC-075.
- Fix direction: put the actor and action first, keep the small words, and split the mechanism from its benefit.
- Example: Illustration: "Vivian says enough of Dunk's faun wine could knock the dragon out. If that works, the party could drive Sir Brandon's sword through its mouth." was the target after a crowded source-last version.
- Sources: PREF-026, PREF-002, EX-033, EX-034

#### RC-014 Short bullets, never box text
- Kind: pattern
- Direction: negative
- Status: failing
- Check: any section is written as narrative paragraphs, or a bullet is long enough that a GM could not paraphrase it at a glance.
- Fix direction: one short bullet per item.
- Sources: PREF-021, EX-049

#### RC-015 "The party", not "you"
- Kind: pattern
- Direction: negative
- Status: failing
- Check: the Summary addresses the players as "you" for something about all the attending characters.
- Fix direction: say "the party"; "you" belongs to the Table Recap.
- Sources: PREF-023, EX-034

#### RC-016 Keep detail that serves its heading
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a bullet carries bookkeeping, precision, a secondary event or a profile that neither helps recognize or understand its selected historical interaction nor changes later choices or understanding of an ongoing situation. A short contextual detail can remain within a meaningful encounter without independently changing future play. Apply relevance across headings, while recognizing that an amount may help tell an offer as history but be unnecessary in the opportunity.
- Fix direction: retain the meaningful event or current action, and only the detail useful to its particular presentation; do not impose a future-effect test on every historical phrase.
- Example: Illustration: the reporting hierarchy is rejected even in the stopping situation; the short mule-offer detail within the Gill encounter is acceptable either included or omitted.
- Sources: PREF-050, PREF-007, EX-009, EX-059, EX-078, EX-079 (SRC-60 clarification)

#### RC-017 Uncertainty and attribution survive
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a claim that the evidence attributes to someone or leaves uncertain is stated as established fact, or a bullet overstates what is known.
- Fix direction: keep the claimant ("X says") and the hedge ("supposed to", "may"); put doubt on the premise.
- Example: Illustration: "Dunk has an undiluted sample of faun wine that is supposed to make almost anything drunk or fall asleep."
- Sources: PREF-009, EX-010, EX-048, EX-050

#### RC-018 Table talk is not established fact
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a bullet presents a player's speculation, or one character correcting another from knowledge they already held, as something learned or established. A character reporting a real discovery still counts.
- Fix direction: base knowledge on what the Session's evidence supplied, not on who was wrong.
- Sources: PREF-008, EX-006

#### RC-020 An obstacle shown without the answer the party already has

- Direction: negative
- Status: advisory (unclear: the connected-threads fixes were dropped without implementation on 2026-10-28; the reason is not recorded)
- Check: a "Standing in your way" bullet stands as if nothing changed, although the party has since gained something that answers it.
- Fix direction: none decided.
- Sources: EX-028

#### RC-021 One name per thing across sections
- Kind: pattern
- Direction: negative
- Status: advisory (unclear: the stale-content fix was closed at the user’s request without a recorded reason; independently supported lifecycle rules remain in RC-010)
- Check: something identified by name in one section is called by an older description in another.
- Fix direction: none decided.
- Sources: EX-029

#### RC-073 Eligible open matters persist across Summaries
- Kind: pattern
- Direction: positive
- Status: failing
- Check: an otherwise eligible matter still open at the stopping point remains represented even if unchanged from the prior Session. Unchanged wording across Sessions is acceptable. Do not omit it or invent variation merely to avoid repetition; within-tier deduplication and actual lifecycle endings still apply.
- Fix direction: assess current eligibility and open state rather than novelty since the last Summary.
- Sources: EX-027, PREF-021 (SRC-60 explicit supersession)

#### RC-075 Optional recognition cues without repeated profiles
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a bullet stacks identifying labels or adds a profile beyond a brief useful recognition cue, or repeats an introduction already supplied in this Summary. A short role or descriptor at first mention in the current Summary is allowed, including for a familiar character; its absence is not a failure. Treat the allowance as optional rather than requiring bare familiar names or mandatory labels.
- Fix direction: use the name with at most a brief useful recognition cue at first mention; omit repeated introductions and profile detail.
- Sources: PREF-049, EX-078, EX-057, EX-047, EX-080 (SRC-60 provisional allowance)

### Last session...

#### RC-022 Past tense, in play order
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a bullet is not in the past tense, or the bullets are not in the order the events happened.
- Fix direction: write events in the past tense and sort by the actual narrated event’s source position, not a thread’s first mention; validate which supporting event anchors the bullet.
- Sources: PREF-027, EX-057

#### RC-023 One main change per thread or encounter
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a bullet tells more than its thread's main change, attaching events from another thread's story, or two bullets tell the same event.
- Fix direction: one short headline per selected thread, event or encounter, telling its most important change.
- Sources: EX-057, EX-078, EX-079

#### RC-024 Only changes that last
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a bullet reports a transient effect (damage taken, moving about), routine treasure or gold, or gold paid. A noteworthy encounter admitted by RC-025 is not a failure here.
- Fix direction: keep historical items to notable changes that persist beyond the Session, plus approved noteworthy encounters.
- Sources: PREF-039, EX-057

#### RC-025 A noteworthy encounter is not lost
- Kind: pattern
- Direction: positive
- Status: failing
- Check: when a meaningful encounter (hospitality, an established contact, a significant information exchange) has no other historical representation, it appears once, even if the open want connected with it is incidental and hidden. Routine colour and logistics need not appear, and no character or scene is owed a bullet.
- Fix direction: judge the encounter's historical value separately from its open-goal significance and lasting effect, and admit it once.
- Sources: EX-079

#### RC-026 Gains are told as gains
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a gained ally, item or favour is described as a profile (weapons, temperament, relative experience) or with payment terms, rather than the gain plus at most the property that makes it useful.
- Fix direction: state the gained capability or relationship in one short sentence; terms belong to "Promises and debts".
- Example: Illustration: the user's golden replaced "A confident halfling with a sling and a dagger who is more experienced than Trout." with "Squints has signed on with the party."
- Sources: EX-047, EX-048, PREF-038 (its goal-support filter predates the unified pipeline)

#### RC-027 Low-impact changes with high lasting consequences

- Direction: positive
- Status: advisory (deferred: the investigation is registered and no cutoff change is approved)
- Check: a change rated low impact but high lasting consequence is missing from history. Report it for the deferred investigation; never fail it.
- Fix direction: none decided.
- Sources: EX-069, PREF-044

- Check: a bullet presented as progress only repeats an open question’s premise, extent, duration or setup without reducing uncertainty about its answer. That information may still qualify as a historical event or a forward fact under the unified definitions.
- Fix direction: assess the bullet under its current heading; do not import the old Revelation publication threshold into history.

### Your goals

#### RC-029 A goal is an end, not a means
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a goal states a proposed method rather than the supported end it serves: the party would not still want it if every other goal were achieved. Where the evidence supports both an independent end and a means, the user accepts ambiguity; usefulness toward another goal alone does not prove failure.
- Fix direction: identify the end from established purpose, without inventing motives; record proposed means separately. A method’s expiry does not itself settle a broader end.
- Sources: PREF-033, EX-035, EX-081, PREF-053

#### RC-030 The outcome only
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a goal contains a lead, clue or source; a reason ("so", "because", "in order to"); a description of the thing wanted beyond naming it; progress or history; or a hedge on commitment ("is considering", "may"); or it claims more than play established, such as a map showing where the treasure is. A reward that defines the goal may stay.
- Fix direction: state the desired outcome, beginning with a verb. The reviewed map reference is a very minor occurrence; preserve the general preference without exaggerating its severity.
- Example: Illustration: "Find the treasure shown on the party's treasure map" was rejected: "this whole map reference is unnecessary".
- Sources: PREF-033, EX-051, EX-052, EX-058, EX-059 (EX-052 supersedes EX-035's "is considering" form)

#### RC-031 A job the party took up shows its outcome
- Kind: pattern
- Direction: positive
- Status: failing
- Check: when the party has taken up a job, its outcome appears as a goal, framed as the outcome (catching the thief) rather than the deal (helping someone for pay). The tension with EX-003, where a goal restating the deal was rejected, is recorded in the source.
- Fix direction: record the job's outcome as a want with its defining reward.
- Sources: EX-056, PREF-033, EX-003

#### RC-071 Narrative priority determines goal order
- Kind: pattern
- Direction: negative
- Status: failing
- Check: the adventure currently driving the party's established choices is ordered below a less central adventure or a side goal. Assess relative priority from the evidence rather than accepting equally-primary labels merely because both adventures matter. Genuine ties remain allowed; within a priority group importance and stable ties decide. Isolated actionability does not outrank narrative priority, and code rather than the writer enforces order.
- Fix direction: classify priority from established direction, preparations and reasons for action, then sort deterministically without named Session exceptions; update prior classification with an evidence basis when focus changes.
- Sources: EX-071, PREF-033, PREF-053, PREF-054 (SRC-60 priority clarification)

#### RC-033 Incidental wants stay hidden
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a minor end whose achievement would change little appears as a goal, for example after only a re-rating, repeated small bargaining or a dramatic proposed method. Judge consequences of achieving the actual end; adventure-level goals are not excluded for low generic impact.
- Fix direction: keep incidental wants in the data but hidden unless new evidence changes their significance; do not invent abandonment.
- Sources: EX-072 (borderline when captured; the boundary was later approved), EX-079, EX-081, PREF-053, PREF-054

### Standing in your way

#### RC-063 State the blocking condition, with its source
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an impediment mistakes the refusal or failure of one proposed method for a condition that actually constrains the supported end, substitutes the absence of a solution or speculation about motives for the actual blocking condition, loses an attributed source, or merely repeats learned knowledge without making its obstructing role clear. The target can be clear from the condition itself; a mechanical goal label is unnecessary, and established useful context about getting past it is not categorically forbidden.
- Fix direction: name the condition that blocks the live pursuit, preserving attribution and making the obstruction understandable in natural speech.
- Example: Illustration: “Gill says Warwick always refuses to sell the mithril chain shirt he displays in his shop.” was judged good.
- Sources: PREF-034, EX-060, EX-023, EX-081

#### RC-035 Not a missing fix, not a future obstacle
- Kind: pattern
- Direction: negative
- Status: failing
- Check: the bullet is the absence of a known fix (which is an opening), or an obstacle that is not in effect at the end of the Session. A danger that will start later, such as a creature that will soon fly, is a threat for "Meanwhile".
- Fix direction: state the condition that blocks now; a way around it belongs under "What could help".
- Sources: PREF-034, EX-037, EX-038

#### RC-036 A scene-local confrontation is not a lasting obstacle
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an obstacle describes only an immediate, scene-local confrontation, or blocks no live pursuit the Summary shows.
- Fix direction: tell the confrontation under "Immediate danger"; keep only distinct continuing obstructions with a live target.
- Sources: PREF-042, EX-067

### What could help

#### RC-074 Opportunities use conditional action and advantage
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an opportunity is a bare resource fact or statement of intent rather than a clear conditional action and useful consequence. “If X, Y” is the required relationship; the literal word “then” is optional and attribution can precede the condition. An essential uncertainty may occupy a second short sentence.
- Fix direction: write what the party could do and the advantage it would gain, retaining source and material uncertainty without inventing a benefit.
- Sources: EX-040, PREF-028 (SRC-60 explicit approval)

#### RC-069 An understandable advantage in concise, natural wording
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an opening lacks an understandable action and useful advantage, has a generic payoff whose meaning is unclear even from context, loses material attribution/uncertainty, or appends redundant precision or explanation. An action such as hiring a helper can suffice without enumerating fees or rebates. Prefer one short sentence; a material condition, source or uncertainty may need a second. A clear contextual benefit need not spell out an obvious mechanism.
- Fix direction: state the action and shortest understandable advantage; preserve material limits and uncertainty, with full contract terms in state rather than compulsory displayed precision. An amount may be acceptable in history without being necessary in the opportunity.
- Sources: PREF-028, PREF-026, PREF-046, EX-061, EX-030, EX-034, EX-074, EX-080 (SRC-60)

#### RC-038 Every opening advances a goal
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an opening advances no goal the Summary shows, however attractive.
- Fix direction: tie each opening to a goal, or leave it out.
- Sources: PREF-035, EX-041 (good under the earlier definition)

#### RC-040 One opportunity per plan
- Kind: pattern
- Direction: negative
- Status: failing
- Check: several bullets are one opportunity, by any of three patterns:
  1. **same trigger, same goal:** they start from the same action and their benefits advance the same goal, including one that only restates the payoff ("she joins" versus "you gain a seasoned fighter");
  2. **a chain:** one bullet's benefit is another bullet's trigger;
  3. **complementary pieces:** each supplies part of what one action needs and the party would use them together (a way in, and the owner kept asleep).
  Alternatives, where either alone would do the job, stay separate, as do distinct resources (RC-007). A chain that crosses into a different goal splits there (RC-062).
- Fix direction: publish one opportunity, written from the first trigger to the advantage it finally yields, keeping the useful terms, source and uncertainty of its parts.
- Sources: PREF-045, EX-040, EX-053, EX-073, PREF-041

#### RC-041 No invented offers
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an opening relies on an agreement, terms, capability, access or cooperation that play did not establish, or is an obstacle worded as an opportunity.
- Fix direction: publish only openings whose action and advantage are supported.
- Sources: EX-055, EX-065, PREF-040

#### RC-042 A supported opening is not hidden because nobody proposed it
- Kind: pattern
- Direction: positive
- Status: failing
- Check: when established access or capability gives a concrete advantage toward a shown goal, that opening is not hidden solely because nobody proposed the action aloud or the actual offer of help did not name that goal. Judge from the run’s kept-and-dropped records; negotiated cooperation and terms still require evidence, and its conditions remain costs rather than proof that it helps no goal.
- Fix direction: allow straightforward capability-to-need matching.
- Sources: PREF-040, EX-065, EX-080

#### RC-043 Held help is not an opportunity
- Kind: pattern
- Direction: negative
- Status: failing
- Check: something the party already holds (an ally who joined, an item in hand) appears under "What could help" as itself. An action that uses held help to gain an advantage is an opportunity, because the action is the trigger.
- Fix direction: keep held help in campaign state and history; an opening names the action that uses it.
- Sources: PREF-047, EX-075 (and the approved direction recorded after it), PREF-038

#### RC-061 The benefit is an advantage, never the goal itself
- Kind: pattern
- Direction: negative
- Status: failing
- Check: an opening's benefit is just reaching a goal, paying its price or terms, or having the item ("if they get it, they have it"), rather than an obstacle overcome or a goal made easier. A plan that ends at the goal ("…they could take the item") instead of at its advantage ("…the owner will stay asleep while they are in the house") fails too.
- Fix direction: state the advantage the trigger gives toward the goal; an approach that simply achieves the goal is not an opportunity.
- Sources: PREF-046, PREF-035, EX-054, EX-074

#### RC-062 A goal can trigger an opportunity toward another goal
- Kind: pattern
- Direction: positive
- Status: failing
- Check: when achieving one shown goal gives an established, specific advantage toward another shown goal, that opportunity appears, written once. Judge from the run's kept-and-dropped records whether it was hidden, for example as generic usefulness. A bare "could help" fails RC-069 only when its useful meaning is unclear from both wording and context; accepted contextual shorthand need not spell out a mechanism.
- Fix direction: treat a goal as a valid trigger; split a chain where it crosses from one goal into another.
- Example: Illustration: "If the party gets Warwick's mithril shirt, Dunk says it is magical armor to wear against the dragon."
- Sources: PREF-046, EX-074 (2026-11-01 reinterpretation)

### Still unanswered

#### RC-044 One bare question about an underlying truth
- Kind: pattern
- Direction: negative
- Status: failing
- Check: a question runs much past ten words or attaches a clue, source or background.
- Fix direction: ask the bare underlying question. The reviewed treasure wording is a minor issue; word count alone is not a meaningful defect in that occurrence.
- Example: Illustration: "Where did the black dragon come from?"
- Sources: PREF-003, EX-019, EX-062

#### RC-045 Not an ordinary unknown
- Kind: pattern
- Direction: negative
- Status: failing
