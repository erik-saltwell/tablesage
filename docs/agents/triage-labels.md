# Work-item status and historical triage labels

For current work, use only the canonical statuses in [the engineering workflow](../../.work-items/workflow.md#canonical-statuses). The item record is authoritative once it exists; [WORK-ITEMS.md](../../WORK-ITEMS.md) mirrors it. A parked substantive proposal is `captured`, not `fleshing-out`.

Older issue documents may contain `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` or `wontfix`. These are historical triage labels, not current item.md status values. Do not mechanically map them to active stages: a readiness label does not prove that implementation began or completed.

When explicitly resuming older work, record its actual current activity in the work-item workflow and carry unanswered questions or declined scope in prose. Do not add a second readiness/status field or bulk-migrate historical records without a request.
